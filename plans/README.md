## Why plan 001 was the one shipped

Plan 001 is the highest-leverage plan that is a real user-facing fix grounded
in repo evidence:

- **It stops data loss.** A successful regeneration overwrote the seller's
  edited title and description (`app/app/page.tsx`, success branch of
  `generate`). Each regeneration also spends one of the ten advisory
  generations.
- **The roadmap names it.** `ROADMAP.md` makes "Regeneration cannot silently
  replace manual changes" an acceptance criterion.
- **The UI was working around it.** The page could only tell sellers to "Copy
  anything you want to keep first".
- **The repo's own gates can verify it.** Vitest in jsdom, typecheck, lint, the
  production build and the offline e2e journey all cover it, with no paid APIs.

Plans 002 and 005 are smaller. 003 and 004 touch the same component, so 001
should land first.

## Direction findings (options for the maintainer, not ranked against bugs)

- **Save and resume a reviewed draft on this device** (ROADMAP item 1, effort L). The in-memory "previous draft" from plan 001 is a first step. A real library needs storage, a naming and verification UI, and a decision on the device-only boundary. Spike it as a design plan.
- **Cross-marketplace adaptation with a field diff** (ROADMAP item 2, effort M–L). Today "Try another marketplace" regenerates from the photos. Reusing the seller's verified facts and showing which fields changed would build on plan 001's two-draft swap.

## Not audited / limits

- There were no live provider calls, so model quality and the 9-second
  per-attempt timeout are unmeasured. The timeout could abort slow but healthy
  free models; check it with production logs before changing it.
- Marketplace limits were not checked against current marketplace
  documentation. The Poshmark title limit of 50 (`lib/marketplaces.ts`) may be
  out of date.
- `globals.css` and the landing and legal pages got only a light review.

## Findings considered and rejected

- **The 846-line studio god component.** Splitting it is not worth it now:
  `docs/untangle-decisions.md` records the decision to keep its coordinated
  async lifecycle together.
- **The cookie allowance can be reset, and concurrent requests can undercount.**
  This is documented as advisory in `README.md` and `docs/reliability-audit.md`.
- **The paste listener re-registers on every render.** Its cost is negligible,
  and it always captures the latest `addFiles`.
- **There are no CSP or frame headers.** There is no authenticated or sensitive
  browser surface, so the impact is low today. Revisit when accounts or saved
  drafts exist.
- **`SYSTEM_PROMPT` lists only three of the four marketplaces.** This is
  cosmetic, because the user prompt names the target marketplace.
- **`pnpm audit --prod` is clean.** It reported no known vulnerabilities.
